## 本轮实现

### 真实报表和统计口径

服务端在当前企业和可见记录范围内汇总，采用同一只读事务快照，支持最多 366 天日期区间。报表不混入其他企业或无权查看的客户关联记录。

- 客户和线索按创建日期统计；线索转换率使用该创建区间内线索的当前转换状态。
- 商机阶段图使用创建区间内商机的当前阶段分布，不表示逐阶段历史转化率。
- 成交统计按实际成交日期，金额使用整数分；跟进按发生日期，待办按上海时区截止日期。
- 无相应业务模块权限的统计不暴露业务信息；平台运营不能直接读取企业报表。

### 客户导入和六类导出

客户导入使用固定中文模板：`客户名称,行业,等级,来源,地区,统一社会信用代码,备注`。支持 UTF-8 / BOM、CSV 引号与换行，最多 500 行、512KB。预校验保存不可变批次与逐行错误，批次有效期 24 小时，仅创建者查看 / 提交；有字段权限限制时依策略处理。

提交仅导入所选有效行，在同一事务重新检查企业状态、负责人、当前权限、重复资料及客户额度。并发不能抢占超额席位 / 客户 / 附件容量；幂等键和版本用于防重复提交与冲突处理。没有自动更新已有客户或导入联系人、线索、商机的功能。

六类导出均依据当前模块、记录与关联权限过滤，客户敏感字段遵守字段策略。CSV 使用 UTF-8 BOM、强制附件下载及公式注入处理；最多 5000 条，超过上限明确报错，不静默截断。导出会写入正常访问审计，但不修改业务记录。

### 私有附件和容量

Railway 私有对象桶已接入真实预览。单文件 1 字节至 5MB，支持 PNG、JPEG、PDF，以及 UTF-8 TXT / CSV，检查扩展名、文件特征、大小及摘要。上传必须关联可写客户，可选同客户商机；下载每次检查当前企业、资料及模块权限并校验文件摘要，返回附件下载，不向前端暴露对象键或长期公开地址。

容量由事务锁和数据库计数维护。上传失败有补偿处理；删除先撤销业务可见性并释放容量，再通过持久清理队列删除对象，失败保留延迟重试。已有占用超出目标套餐时，既不能缩小套餐容量，也不能通过给企业换套餐绕过限制。附件不支持任意可执行文件、文件版本或自动病毒扫描。

### 站内提醒、运维和账号恢复

真实预览开启约每五分钟的待办检查。到期 / 逾期提醒属于执行人，按日期、任务版本和执行人防重复；完成、重开、转交与权限变化影响当前可见性。提醒是站内功能，没有外发短信、邮件或即时通讯通知。

平台运维展示真实数据库和对象存储探测、资源摘要与后台任务状态。提醒 / 清理失败会记录错误并提示；失败对象清理延迟重试。页面不展示客户业务正文、凭据或备份下载地址，没有外部告警接收人。

密码找回后端和页面已实现：平台绑定核验邮箱，统一申请提示、15 分钟 / 5 次处理限制、30 分钟一次性链接、仅保存令牌摘要、投递失败作废、成功找回撤销旧会话。正式 SMTP 未配置，因此现有预览仍关闭邮件找回。隔离验收使用内部假 SMTP 和 `example.invalid` 收件人，没有发送客户邮件。

## 数据和权限实现

版本为 Vue 3 / TypeScript、Java 21、Spring Boot 3.5.16、原生 PostgreSQL 18.6。未采用 SQLite。

Flyway V5 为增量迁移，新增五个交付权限、套餐容量、附件计数、导入批次、附件、提醒、清理队列及运维 / 恢复元数据；租户范围的强制 RLS 表增加到 17 张。运行账号无超级用户或 BYPASSRLS，迁移账号独立。原 V1～V4 与 P0～P1-C 功能继续保留。

接口由 DeliveryController、DataService、AttachmentService、NotificationService、OperationsService 和 RecoveryService 分工，复用服务端会话、CSRF、企业上下文、权限和版本协议。前端由 DeliveryWorkspace 与 RecoveryPanel 接入真实 API。附件窗口采用居中、视口限高、内部滚动及键盘关闭，沿用此前弹窗修复；本轮没有浏览器视觉复验。

## 备份、流水线与试点的完成边界

已准备 `server/ops/backup.py`、`restore_backup.py`、独立备份镜像和启动配置；支持一致性数据库快照、私有附件、AES-256-GCM 加密、存储读回校验和独立恢复。一次隔离演练恢复 33 张表、900 行、一个非空附件，验证 17 表 RLS、5 次迁移、认证解密及篡改拒绝；临时对象已经清理。该演练使用虚构隔离数据，不是原预览全库备份。

用户随后明确授权专用 `crm_backup` 数据库账号，该账号已创建并验证全表 SELECT、业务表无写权限及 TLS。原预览每日北京时间 02:00 加密全库备份，并启用每次快照的本地独立恢复校验。首份私有加密对象已保留，恢复核对 33 表、279 行、17 表 RLS 和 5 次迁移，当前附件数为 0。授权前拒绝记录已解决，没有把管理员账号用作日常备份账号。手动恢复工具仍未用于生产切流，详细证据见 `P1-D备份启用验收.json`，运维与回滚见 `P1-D上线运维与试点手册.md`。

`.github/workflows/verify-and-container.yml` 已准备前后端校验、容器构建和手动发布 / digest 记录，但没有接入正式 GitHub / 容器注册表，在线流水线未运行。当前 Railway 预览继续通过摘要校验的源码包和官方 Maven / Java 21 镜像构建。源码和文档由现有项目的关联 Git 保存，演示站点保持原私有访问范围。
