# 彬彬 CRM · P0 后端与云测试交付

版本：0.2.0；日期：2026-10-12；产品模式：用户自有、统一托管、多企业订阅。
本轮在独立云测试环境开发，未使用用户生产服务器。

## 1. 在线入口和本轮结论

真实登录与客户操作：https://crm-java-api-crm-test.up.railway.app
完整流程演示：https://binbin-crm-preview.zengb-12.chatgpt.site

真实版本已经运行 Java 21 / Spring Boot 3.5.16、Vue 3 / TypeScript 和原生 PostgreSQL 18.6。
Flyway 固定为 11.18.0，V1 迁移已应用，后续部署验证迁移摘要；不采用 SQLite 或 D1。
本轮覆盖 P0 基础与客户基础验收，不代表全部销售模块或收费试运营已经完成。

## 2. 已实现能力

|能力|实现与用户可见行为|
|---|---|
|密码登录|BCrypt 密码摘要；账号失败限制；不向客户端返回会话原始凭证|
|安全会话|随机不透明令牌；数据库仅存 SHA-256 摘要；HttpOnly、Secure、SameSite=Lax Cookie；8 小时有效期|
|请求保护|业务写入要求 CSRF；来源校验；API 不缓存；异常不返回 SQL、堆栈或密码|
|账号检查|每次请求检查账号状态、认证版本、会话有效期和撤销状态；退出立即撤销|
|企业选择|仅列出当前账号有效成员关系中的企业；当前企业写入服务端会话|
|权限检查|逐次读取有效成员和角色；平台运营和企业系统管理员不会自动获得客户权限|
|订阅状态|到期可受控查看，禁止写入；暂停企业拒绝客户业务读取与写入|
|客户操作|分页、名称搜索、详情、新增、编辑；负责人限定当前企业有效成员；销售只能向自己分配|
|并发与重复提交|创建请求按企业、成员和幂等键防重；内容冲突返回 409；编辑按记录版本检查|
|数据库防护|业务表强制 RLS；复合外键限制跨企业关联；运行角色不具备超级用户或 BYPASSRLS 权限|
|审计|登录、退出、企业选择与客户创建 / 更新记录数据库审计；运行角色只能追加业务审计|
|页面操作|密码登录、已加入企业切换、客户列表、分页、查看、新增与编辑；会话与 CSRF 不存 localStorage|

|账号|角色与访问范围|

## 4. API 协议

|方法|路径（/api/v1 前缀）|范围|
|---|---|---|
|GET|/health|部署就绪、数据库连接与版本|
|POST|/auth/login|用户名 / 密码；设置会话 Cookie；返回自身信息、CSRF 与已加入企业|
|GET|/auth/session|检查当前会话并返回自身状态|
|POST|/auth/logout|校验 CSRF，撤销会话并清除 Cookie|
|GET|/tenants|当前账号有效成员关系中的企业|
|POST|/auth/active-tenant|校验成员关系并切换当前企业|
|GET|/customers|page、pageSize、q；单页最多 100 条|
|GET|/customers/owners|当前角色可分配的负责人|
|GET|/customers/{id}|按当前企业与记录权限查详情|
|POST|/customers|需要 Idempotency-Key、CSRF；返回新建或重放的同一客户|
|PATCH|/customers/{id}|需要 expectedVersion、CSRF；不接受 tenantId 或负责人重分配|

未知 JSON 字段返回 400，认证失败 401，权限不足 403，不存在或不可见的记录 404，版本 / 唯一性 / 幂等冲突 409，数据库不可用 503。
错误体统一包含 code、message、traceId；追踪编号由服务端生成。
信用代码为可选项，提交时校验 18 位编码校验位；本轮没有接入工商登记查询。

## 5. 表结构与隔离

全局身份 / 控制表：iam_user、sys_tenant、sys_tenant_member、sys_member_role、auth_session、auth_login_limit、iam_audit。
租户业务表：crm_customer、crm_customer_share、sys_idempotency_request、sys_audit_log。

业务事务用认证会话中的企业 ID 设置事务级 crm.tenant_id，结束后自动清除；没有上下文时 RLS 返回零条。
客户负责人、共享成员和业务审计使用 tenant_id 复合引用，数据库拒绝跨企业关联。
运行角色 crm_runtime 与迁移 / 表所有者 crm_migrator 分开；启动时检查角色权限和 4 张业务表的强制 RLS。
RLS 是业务隔离的补充措施，应用仍校验成员、角色、共享和订阅；它不代表完整基础设施安全验收。
云数据库位于项目私有网络，没有开放公共数据库 TCP 代理；Java 数据库连接强制 TLS。

## 7. 云部署和源码交付

Railway 项目：Binbin CRM · Cloud Test，环境：crm-test。
项目地址：https://railway.com/project/1807b9ed-791a-4e66-b77a-890d6b802621
服务：crm-java-api、Postgres；初始化和验收使用一次性辅助任务，完成后清除其数据库 / 登录凭证引用。
数据库持久卷 500 MB；Java 服务配置上限 1 GB 内存、1 vCPU；这些是测试配置，不是生产容量或费用承诺。

当前连接器只能接入 GitHub 仓库或公开镜像，未接入 GitHub，因而本轮使用官方 Maven / Java 21 镜像在启动时构建经过 SHA-256 校验的源码包。
此方式用于当前云测试；源码已经提供标准 Dockerfile（多阶段构建、非 root JRE）和 railway.toml，下一阶段改为仓库构建、镜像版本固定和独立迁移任务。

代码与本记录通过原 Site 关联 Git 仓库保存。数据库凭证、测试密码和短期源码推送凭证不进入仓库。
运行参数模板位于 server/.env.example；开发初始化脚本位于 server/test-support/bootstrap_database.ts。
自建 / 自定义域名部署时，Docker 构建指定 VITE_RUNTIME_MODE=live；亦可用 /?mode=live 进入真实工作区，/?mode=demo 浏览演示。
