## 在哪里操作

客户企业端登录、选定企业后，在**左侧导航**中操作。企业管理员同时拥有销售主管等业务角色时，可以配置与办理对应业务；纯技术管理员不会因此获得财务或客户业务权限。

| 左侧入口 | 使用人 | 具体操作 |
|---|---|---|
| 经营指挥台 | 管理层、主管、销售 | 查看本人、团队或获授权企业范围的分析，点击图表下钻 |
| 自动化规则 | 企业管理员，且有相应业务写入权限 | 新建规则、保存草稿、发布、手动执行、到期检查、执行记录、停用 |
| 业务扩展工作台 | 有对应业务权限的成员 | 选择对象、搜索、查看资料与附件、维护扩展字段、快捷新增、导出、返回原模块办理审批履约 |
| 业务通知 | 通知接收人 | 查看仍有权访问的业务提醒、标记已读 |
| 新增对象权限 | 企业管理员 | 限制订单、开票、支出、目标、提成、周报的角色读写权限 |
| 行业配置 | 获授权管理员 | 新建扩展字段、设置字段类型、必填项及角色权限 |
| 外链表单 | 企业管理员，且有对应业务写入权限 | 创建线索或服务需求表单，复制一次显示的链接、撤销链接 |
| 数据迁移 | 企业管理员，且有对应业务写入权限 | 下载模板、上传 CSV、预校验、下载错误清单、核对整批入库、查看批次 |
| 试点检查 | 企业管理员，且有全企业业务读取权限 | 查看订阅、组织、复核人、业务闭环、附件、邮件、调度、备份等检查项并归档 |
| 扩展功能套餐（平台运营端） | 产品方平台运营人员 | 配置自动化、工作区、迁移开关及规则、执行、表单、提交、迁移行数额度 |

平台运营端给产品方使用；客户企业端给租用 CRM 的公司使用。流程演示端使用浏览器演示数据，P7 的真实规则、迁移和试点记录在客户企业端办理。

## 自动化如何生效

1. 选择业务对象、执行成员、触发方式，配置最多 10 个“全部满足”条件和 3 个受控动作。
2. 保存后为草稿，核对后发布。修改已发布规则会重新转成草稿，需再次发布。
3. 条件规则处理发布后的业务创建或更新事件；定时规则按上海时间指定小时开始，每分钟分批检查；手动规则选择可见记录执行。
4. 可用动作包括客户等级填充、跟进待办、站内提醒、分配/回收客户或线索、发起报价审批、批准报价生成订单草稿。
5. 执行时重新检查执行成员、配置人、当前角色、订阅、套餐、原记录权限和规则版本。自动化不能自动批准报价、确认回款或锁定提成。
6. 同次执行中的业务变更在一个事务内；任一步失败会回滚这些变更，另行保留失败尝试。失败最多尝试 5 次；权限或版本变化会阻止执行。
7. 同一手动请求、同一事件、同一天同一记录都分别去重；自动化动作不会继续递归触发规则。

后台开关为 `CRM_AUTOMATION_SCHEDULE_ENABLED=true`。页面显示调度开关状态；“执行到期检查”可由管理员手动触发检查。执行记录含状态、版本、次数和尝试历史，不在日志中复制业务敏感字段。

## 扩展资料与接口

- 工作区支持客户、线索、商机、报价、订单、合同、回款、服务工单、开票、支出、目标、提成、周报、产品。联系人沿用原模块能力。
- 新权限只能收紧原授权，不会扩大客户、部门、所有人或财务可见范围。成本、提成隐私仍由原模块控制。
- 扩展字段具有独立读写角色、必填及类型校验、值版本和源记录版本；隐藏字段的值不会通过新旧扩展接口返回。
- 已确认或锁定的财务记录保留只读扩展历史。附件沿用 5MB 校验、同企业共享容量、文件哈希、授权下载和删除清理队列，加入加密备份清单。
- 新开放查询为带签名的 `POST /api/v1/inbound/records`，按 orders.read、invoices.read、expenses.read、targets.read、commissions.read、weeklies.read、products.read 分别授权。时间窗 300 秒、随机数防重放、每密钥每分钟 60 次，并记录读取审计。
- 签名仍是 HMAC-SHA256；规范串为 `POST + 换行 + 路径 + 换行 + 时间戳 + 换行 + 随机数 + 换行 + SHA256(原始请求体)`。使用一次显示的密钥随机段签名，不能将密钥放入 URL。
- Webhook 增加报价、订单、合同、开票、支出、目标、提成、周报事件，沿用持久队列、重试和投递前授权复核。事件只携带元数据。
- 外链只允许固定线索/服务需求字段。至少提供电话或邮箱并同意本次联系用途；链接有有效期且可撤销。每表单同一来源每小时最多 10 次，另有套餐月度额度；重复提交返回同一回执，不返回内部业务 ID。
- 界面延续深色玻璃风格、左侧导航、居中可滚动弹窗；手机端支持资料、快捷新增、迁移、规则检查及外链填写。审批和资金状态转换继续在原业务模块办理。

## 数据迁移操作

| 模板 | 核心依赖与入库行为 |
|---|---|
| 线索 | 联系人、公司及联系资料；归属当前导入成员 |
| 产品 | 产品编码、名称、类型、单位、售价/成本/税率；通过原产品服务校验 |
| 销售订单 | 可见的已批准报价编号；只创建未确认订单 |
| 开票申请 | 可见合同编号；创建开票草稿，不能直接登记发票 |
| 支出 | 有效资金账户、收款方、金额、日期和付款流水；创建支出草稿，不记入已确认资金账 |
| 业绩目标 | 成员登录账号或“部门：部门名称”、周期及目标金额；沿用原范围校验 |
| 销售周报 | 周起始日及结构化工作内容；创建本人周报草稿，后续独立审批 |

CSV 使用 UTF-8、保持下载模板的表头顺序，每批最多 200 行、512KB。预校验保留逐行错误；有错误的批次不能提交。预校验后的确认有效期为 24 小时，提交时重新检查资料、权限及月度额度。

同一批次在一个事务中入库，任何一行失败都回滚整批。重复确认同一请求不会重复建单。成功入库后应通过原业务模块更正或作废，不提供删除整批已生效业务的按钮。客户、联系人等已有导入能力保留在原“导入导出”入口。

建议按依赖顺序准备：组织成员 → 客户/联系人/产品/线索 → 商机及批准报价 → 订单/合同 → 开票与回款 → 目标、周报及提成。初次迁移先用小批量虚构数据演练。

## 试点与正式使用

试点检查是准备向导与核验记录，不代表客户已签收。产品方与试点企业仍需指定销售、主管、财务、客服和管理员，在获准数据范围内完成活动到售后及提成的完整业务演练，并核对授权、指标、导出、附件及恢复记录。

正式邮件参数是否存在与实际投递是否成功分开核验。真实邮箱投递、正式凭据及客户试用反馈需要参与方提供；本轮不向外部人员发送测试邮件或通知。

V26～V28 新增 12 张租户表，均启用 FORCE RLS。加密备份覆盖新增数据和工作区附件，旧 V25 备份仍受支持。备份保留期延续 30 天、至少 3 份成功备份，恢复演练在独立恢复数据库执行，不覆盖业务数据库。
