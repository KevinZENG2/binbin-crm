## 体验路径

1. 使用已有 `owner` 和此前交付密码，选择“星澜科技 · 测试企业”，进入真实 CRM 工作台。
2. 新增客户后，从该行“商机”进入客户范围的看板，创建商机，填写预计金额、成交日期和下一步。
3. 打开商机，点击“推进阶段”；填写目标阶段、原因和下一步。也可以拖动商机卡片到相邻阶段，随后在窗口确认。
4. 从商机资料“记录跟进”保存沟通结果；从“安排待办”设置执行人和截止日期，两项各自保存。
5. 在“跟进待办”筛选未完成、逾期、已完成及自己的任务；完成后记录时间，必要时可重新开启。
6. 合格线索转换客户后，可以点击“创建来源商机”。来源固定为已转换到该客户的线索；转换和商机创建是两次独立事务，不会把旧 P1-B 转换流程变成部分成功。

所有新弹窗使用屏幕固定遮罩、居中布局、最大视口高度和内部滚动；标题、操作区保持可见。打开时锁定背景滚动，支持 Escape、焦点限制和关闭后焦点恢复。页面适配窄屏；当前验证限制详见验收章节。

## 商机阶段和金额

|当前阶段|可选择|
|---|---|
|初次接触|需求确认、丢单|
|需求确认|初次接触、方案讨论、丢单|
|方案讨论|需求确认、报价谈判、丢单|
|报价谈判|方案讨论、签约准备、丢单|
|签约准备|报价谈判、成交、丢单|
|成交 / 丢单|资料与历史只读，本轮不提供重开|

开放商机每次变化需要原因和下一步。成交需要正数的实际成交金额，丢单需要原因。预计金额和成交金额分别保存，均使用整数“分”，不使用浮点数计算，也不表示实收回款。来源客户和线索关联创建后固定；其他开放资料编辑使用显式版本。

阶段请求同时保存当前阶段、金额 / 时间、追加历史、审计与防重复请求结果。失败全部回滚。同一请求编号与相同内容可重试；内容变化冲突。两个不同请求并发推进同一版本，最多一个成功。历史包含创建事件和阶段变化，普通资料编辑记审计，不添加伪造的阶段事件。

看板每列显示最近 12 条。列数量和金额由服务端统计全部可见记录，不能把前 12 条当作全部统计；“查看该阶段全部”进入分页列表。成交列汇总实际成交金额，其他列汇总预计金额。拖动仅打开阶段确认窗口，确认后才写入。

## 关联与权限

商机必须同时满足商机模块及其记录范围、所属客户读取权限。写入还需相应商机写入范围和客户写入权限；客户共享不会自动共享该客户全部商机。跟进继承客户权限，关联商机时还需该商机权限。待办按执行人及对应模块范围访问，独立待办可以不关联客户；关联资料时追加客户和商机权限检查。

全部、本部门和本人范围按各角色分别合并读和写；广范围只读角色不会扩大写入范围。本部门不包含子部门。将任务或商机交给成员时，检查该成员有效、模块可写及关联资料可见性，避免把成员无法查看的业务指派给他。

角色、共享、部门或成员变化在后续请求重新计算。撤销来源线索权限时，商机中的来源编号和名称隐藏；来源关系不会因此删除。撤销关联商机权限后，商机及该商机的跟进 / 待办不再通过其他模块泄露。只读支持授权仍仅包含客户，不包含 P1-C 的业务正文。订阅到期允许受控读取，拒绝写入；企业暂停拒绝业务读取。

跟进和商机备注按模块 / 记录整体保护，客户备注的字段开关只控制客户字段。本轮不提供这些模块的逐字段权限、商机独立共享、自定义销售阶段、批量转交或单独套餐额度。

## API 和迁移

|API|行为|
|---|---|
|`GET /api/v1/sales/summary`|按当前权限返回工作台计数；无模块权限的计数为 null|
|`GET /api/v1/opportunities`|搜索、客户 / 阶段筛选、分页|
|`GET /api/v1/opportunities/board`|七阶段汇总和每列最近 12 条|
|`GET /api/v1/opportunities/owners`|当前写入范围中的有效负责人|
|`GET /api/v1/opportunities/{id}`|当前可见资料和编辑能力|
|`POST /api/v1/opportunities`|幂等新增、所属客户 / 已转换线索检查|
|`PATCH /api/v1/opportunities/{id}`|开放资料的显式版本编辑|
|`POST /api/v1/opportunities/{id}/stage`|有原因的阶段推进及原子历史|
|`GET /api/v1/opportunities/{id}/history`|按版本倒序分页的历史|
|`GET /api/v1/tasks`|状态、自己的待办、客户 / 商机筛选与分页|
|`GET /api/v1/tasks/owners`|有效执行人及当前模块写入范围|
|`GET /api/v1/tasks/{id}`|待办详情及完成 / 重开能力|
|`POST /api/v1/tasks`|幂等新增，检查指派及关联资料|
|`PATCH /api/v1/tasks/{id}`|未完成待办的显式版本编辑|
|`POST /api/v1/tasks/{id}/complete`|幂等完成，记录时间及版本|
|`POST /api/v1/tasks/{id}/reopen`|幂等重开，清空完成时间及更新版本|
|`GET /api/v1/activities`|客户 / 商机、搜索和分页的时间线|
|`GET /api/v1/activities/{id}`|原始跟进详情|
|`POST /api/v1/activities`|幂等追加跟进，验证发生时间|

Flyway V4 新增 `crm_opportunity`、`crm_opportunity_history`、`crm_activity`、`crm_task`，以及六个角色模块开关。从既有客户策略初始化新模块开关，不修改既有客户策略；角色版本递增，旧管理请求需刷新。新企业与独立开发种子也设置新字段。

四表强制 RLS，启动守卫检查十三张范围表。复合外键保证同一企业及同一客户的商机关联；来源线索复合外键保证来源已转换到该客户。运行角色对阶段历史和跟进只有读取 / 插入权限，无更新 / 删除权限。沿用非超级用户、独立迁移角色、JDBC TLS、CSRF、工作区版本检测、统一错误和审计。

日期在 2000 至 2100 年内；待办逾期以 Asia/Shanghai 日期计算。沟通发生时间需在 2000 年之后，最多允许当前时间之后五分钟的时钟误差。跟进不会发送邮件。整数请求字段拒绝小数值，避免金额“分”被悄悄截断。

## 验收与交付边界

已通过 24 项 Java 检查、Vue / TypeScript 构建，以及最终隔离原生库 P0 45 / P1-A 61 / P1-B 87 / P1-C 123 项检查和 9 项停机前数据库核验。六家新建验收企业已暂停，临时服务停止，凭据清空。原预览 PostgreSQL 18.6 从 V3 迁移到 V4，发布后 35 项 HTTPS 检查通过，线上 HTML / JavaScript / CSS 与最终构建逐字节相同。

逐项原生接口 / 数据库结果见 `P1-C完整验收结果.json`；构建及摘要见 `P1-C验收结果.json`；云发布、迁移、线上资源及只读检查见 `P1-C部署记录.json`。

完整写入验收只使用新建临时原生 PostgreSQL 中的虚构资料，原预览只执行正常登录、自己企业选择、GET 和退出。临时验收企业完成后暂停，故障触发器移除，保存证据后停止临时服务并清空凭据。

测试覆盖并发阶段 / 待办、错误版本、原子回滚、金额及状态、来源关联、部门与组合角色、共享撤销、模块撤销、到期 / 暂停 / 支持授权、RLS、关联外键和 TLS。两请求并发检查不是性能压测。浏览器视觉和鼠标端到端未执行，本环境没有可用的浏览器自动化能力；生产备份恢复、批量负载、提醒投递和企业试点留待 P1-D。
