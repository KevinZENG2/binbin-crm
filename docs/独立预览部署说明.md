# 独立预览部署说明

版本：P8 0.23.0 / V30。此包用于在支持 Docker Compose 的隔离环境验证和演示 CRM，使用虚拟企业与虚拟客户数据。源码、构建及启动不需要 Railway OAuth、Railway 私有发布对象或旧平台密钥。

## 包含内容

- `compose.preview.yaml`：CRM 应用、PostgreSQL 18、私有 HTTPS S3 兼容存储、一次性配置及桶初始化。
- `Dockerfile.preview`：前端构建、Java 打包、独立迁移目录和非 root 运行。原 `Dockerfile` 不变。
- `server/ops/preview/prepare.py`：生成随机凭据与 30 天预览证书，拒绝覆盖已有配置；输出不含凭据值。
- `server/ops/preview/init_postgres.sh`：仅在全新 PostgreSQL 数据卷上初始化独立运行与迁移角色。
- `server/test-support/verify_portable_preview.py`：真实容器启动、数据库 TLS、RLS、认证、P8 场景、HTTPS 附件和重启持久化检查。

独立存储使用从 MinIO 最后安全发布源码构建的隔离预览实例。其社区仓库已归档，因此这里只将其作为虚拟资料的预览依赖，不作为商业出租产品的生产存储选型；正式托管环境应配置持续维护的 HTTPS 对象存储。该判断依据见 [官方发布](https://github.com/minio/minio/releases/tag/RELEASE.2025-10-15T17-29-55Z)。

## 在隔离容器环境启动

从完整 GitHub 仓库执行，需 Docker Compose v2、Python 3 和 OpenSSL：

```sh
python3 server/ops/preview/prepare.py
docker compose --env-file .crm-preview/compose.env -f compose.preview.yaml config --quiet
docker compose --env-file .crm-preview/compose.env -f compose.preview.yaml up -d --build
```

首次构建需要下载依赖；数据库和私有存储就绪后再启动应用。默认仅向宿主机回环地址开放 `http://127.0.0.1:8080`，数据库、S3 API 与存储控制台均不开放宿主机端口。

企业端 `/?account=owner`、平台后台 `/?account=platform-operator`、客户门户 `/?portal=1` 和演示端 `/?mode=demo` 共用此应用。虚拟账号的初始密码位于当前环境的 `.crm-preview/secrets/login_password`，应由操作者在受控环境查看；不写入文档、源码、CI 日志或镜像。

如用于有 HTTPS 网关的独立云预览，先在一个全新目录准备：

```sh
python3 server/ops/preview/prepare.py --base-url https://YOUR_PREVIEW_DOMAIN
```

HTTPS 模式会启用 Secure Cookie；网关必须使用有效 HTTPS，且回源至该应用。同源地址不能只在浏览器侧替换。此 Compose 文件不是 Render Blueprint；Render 仍需按其服务模型配置应用、数据库和正式对象存储，完成账号连接后再实际部署。

## 凭据、权限与数据

随机凭据及证书保存在 `.crm-preview`，该目录同时被 Git 和 Docker 构建上下文排除。一次性初始化服务只将所需凭据复制至各服务的私有卷：应用不获得数据库管理员密码，数据库和应用不用存储 TLS 私钥，私有根 CA 的签发私钥不挂载给任何运行服务。

应用进程使用 UID 10001；数据库运行角色保持 `crm_runtime`，无 superuser、无 BYPASSRLS、无建库和建角色权限。迁移角色保持 `crm_migrator`，强制租户 RLS 检查继续执行。数据库使用 `sslmode=verify-full`，Java S3 客户端验证 HTTPS 证书；没有关闭证书检查。

应用和数据库重启会保留命名卷。重新运行准备程序不会换掉原密码。已有数据卷与凭据须成对保管，替换或到期更新证书、轮换密码应单独操作。预览证书有效 30 天，不将其作为长期生产证书。

AI 总开关默认关闭，也不注入真实供应商 Key；新增九个场景默认关闭。首次真实调用仍须配置新的供应商密钥、模型、灰度与小额预算，不能将本次容器验收称为真实 AI 调用验收。

## 验证与边界

GitHub Actions 的 `Verify independent CRM preview` 工作流使用独立虚拟环境运行完整启动探针，产出 `portable-preview-acceptance.json`。只有该次运行成功，才记录容器启动与持久化验收通过；本地证书测试通过不替代 Docker 验收。

此包不创建云账号、不建立公开网址、不迁移旧 Railway 数据，也不包含新的云端加密备份和隔离恢复验收。对象存储中的报价字体还需按原发布流程配置，正式邮件服务亦需单独配置和投递核验。

原环境数据、附件和历史备份仍按 [P8 发布恢复记录](P8发布恢复记录.md) 处理；替代托管路线见 [云预览部署方案](云预览部署方案.md)。
