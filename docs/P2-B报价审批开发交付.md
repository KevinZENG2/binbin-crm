# P2-B 报价审批开发交付

版本 v0.8，2026-10-13（北京时间）。当前为用户自有多企业订阅 CRM 的云测试版本，继续托管云预览，不接入用户服务器。

## 开发阶段

整体共有五个大阶段，编号 P0～P4：P0 基础架构；P1-A～D 基础 CRM、组织权限和交付运维；P2-A 产品报价、P2-B 审批、P2-C 合同、P2-D 回款；P3 工单 / SLA / 知识库 / 营销与集成；P4 行业配置 / 客户门户 / AI。P3 / P4 后续可再按业务拆分。本轮是 P2-B，下一阶段 P2-C。

## 操作入口与角色

进入 [客户企业端](https://crm-java-api-crm-test.up.railway.app/?account=owner)，原测试账号密码登录、选择企业。客户销售业务在真实 Java / PostgreSQL 工作区操作；平台运营端仍供你开通企业和管理订阅；流程演示端保持本地虚构资料。

|操作|入口|操作人|
|---|---|---|
|配置另一位销售经理|企业管理 → 组织成员，完成新成员首次改密|客户企业管理员|
|授予审批与资料权限|企业管理 → 角色权限 → 销售经理 → 审批指定报价，同时授予报价、客户及关联商机读取权限|客户企业管理员|
|选择审批人并提交|报价 → 查看 / 版本 → 提交审批 → 搜索并选择销售经理 → 提交审批|获准管理该报价的销售|
|处理待我审批|顶部「报价审批」 → 查看 → 填意见 → 批准当前版本 / 驳回并记录原因|指定的销售经理|
|查看记录|报价 → 查看 / 版本 → 审批记录，点击提交版本查看原报价|当前获准读取该报价的成员|
|驳回后重提|编辑草稿 → 按意见修改 → 保存 → 再次选择审批人提交|报价负责人或获准管理者|
|批准后修改|查看当前版本 → 填重新修改原因 → 转回草稿修改 → 编辑并重新提交|获准管理者|
|取消审批|待审批报价 → 撤回草稿，或填原因作废|获准管理者|

单独的企业管理员角色不自动获得业务读取或审批权。`owner` 示例账号兼任管理员和销售经理，但不能审批自己创建或自己提交的报价；需要配置另一位完成首次改密且有资料权限的经理。系统不会为此擅自创建真实人员账号或发送邀请邮件。现有示例销售账号为 `alice`、`bob`，在登录页手动填写用户名；可用销售账号创建属于自己的报价并指定 `owner` 审批，再切换 `owner` 进入「报价审批」。示例账号可用状态以当前企业配置为准。

## 审批规则

本期为单级指定经理。审批人必须是本企业有效销售经理、账号有效且完成首次改密，拥有独立报价审批开关，并能在当前记录范围内读取报价、所属客户及关联商机。提交时筛选这些条件，实际审批时重新验证；审批人选择不自动扩大资料范围或共享客户。

提交人和报价人按用户身份校验，禁止自审。只有指定经理可批准或驳回，其他经理即使能读取该报价也不能代审。审批不要求目录维护、报价编辑或客户编辑权限，允许“有审批权、无修改金额权”的经理。

提交后锁定明细。驳回必须填写原因；批准可填写意见。处理同时更新报价版本、审批结果、不可修改的版本快照、审批事件和审计。撤回 / 待审批作废取消原请求，迟到的审批无效。已批准报价不能直接编辑或撤回，需填写原因转回草稿；原批准历史保留，但不再适用于新版本。再次提交新建独立审批请求。

报价有效期以北京时间日期为准；报价过期不能批准或驳回，先撤回调整后重提。企业订阅到期保留受控读取、禁止审批和业务写入；企业暂停则沿用现有阻断。支持授权与平台运营不自动取得报价或审批资料权限。

V6 历史待审批报价没有指定审批人，不自动补批；撤回后按新规则重新提交。

## 实现与数据保护

V7 新增 `quote_can_approve`，仅允许销售经理角色并要求报价读取权限。旧客户端省略该字段时保留原配置。新增两张强制租户 RLS 表 `crm_quote_approval` 和 `crm_quote_approval_event`；当前共 40 张公开表、24 张强制 RLS 表、7 次迁移。

审批请求保存提交版本、报价与金额快照、有效期、审批人 / 提交人姓名及单级规则快照，引用不可修改的报价版本，并校验 SHA-256。运行账号不能更新这些快照或指定人员，不能删除审批请求；审批事件仅允许新增 / 读取。报价的版本锁、请求幂等、每报价最多一条待处理请求和事务保护并发与重复处理。报价修改、审批记录和审计必须共同成功，否则全部回滚。

|API|用途|
|---|---|
|GET `/quotes?mine=true`|当前权限下待我审批的分页队列|
|GET `/quotes/{id}/approvers`|当前报价可用经理搜索和分页|
|POST `/quotes/{id}/submit`|带 `approverMemberId` 和 `expectedVersion` 提交|
|POST `/quotes/{id}/approval/approve` 或 `reject`|带 `approvalId`、`expectedVersion`、`reason` 处理|
|GET `/quotes/{id}/approvals`、`/{approvalId}`|审批记录、报价 / 规则快照和事件|
|POST `/quotes/{id}/withdraw`、`void`、`revise`|撤回、作废、批准后转回草稿|

金额、报价历史、中文字体与分页 PDF 沿用 P2-A。PDF 展示所选版本的草稿 / 待审批 / 已批准 / 已驳回 / 作废状态；内部审批不代表客户接受报价或电子签署。

备份 / 恢复扩展精确支持 V5、V6、V7。V7 独立恢复核对完整表集合、属主、迁移、强制隔离及 7 张产品报价审批表的内容摘要。原每日任务、原密钥、原预览数据库和保留前缀保持，仍为北京时间 02:00、30 天并保护最近 3 份成功备份。

## 验收与边界

真实写入验收仅使用全新无持久卷的原生 PostgreSQL 18、虚构企业和私有测试对象前缀。原预览只进行正常认证、自选企业、GET / 退出及必要的发布迁移。本期本地 Java 39 项、领域测试 19 项、运维测试 17 项与前端构建通过；云构建 38 项通过 / 1 项字体测试跳过，实际隔离 API 的批准报价 PDF 和本地中文 / 字体 / 状态测试补充通过。完整云套件有最终完成标记：525 项旧模块回归、73 项 P2-B、11 项数据库 checkpoint，发布后 76 项 HTTPS 只读检查分别通过。V7 隔离恢复实际核对 40 表、1,335 行、24 张 RLS 表、7 次迁移及 1 个 84,000 字节附件；7 张商业表内容摘要一致。临时对象已确认删除，原保留备份仍可用。发布前后 owner 当前企业可读取的六类原有业务资料数量与摘要一致（仅限该账号可读范围）；示例销售 `alice` 的现有登录、报价写入和产品读取权限也已通过只读核对。升级后的首次真实每日任务仍待观察。具体部署 ID、构建资源摘要、恢复与清理结果见 `P2-B验收与部署记录.json`。部署 SUCCESS 本身不视为断言通过，必须有逐阶段结果及最终标记。

没有浏览器视觉 / 鼠标端到端、真实手机设备或性能压测；本期不标记这些验收通过。正式 SMTP、独立密钥交接、真实客户试点、异地副本和外部告警继续保留待办。

## 下一阶段

P2-C：从当前有效且已批准的报价建立合同，关联客户与商业快照、合同编号、附件、签订 / 生效 / 终止、受控变更及收款计划。必须检查当前批准与报价版本、金额、有效期匹配，拒绝未批准、已撤回、已修改、作废或过期报价。P2-D 再登记与确认回款、冲正和对账；不混用 SaaS 订阅续费记录。

本期不包含审批代理、转签、多级流程、自动规则分流、邮件审批、电子签章、合同、回款或在线支付。
