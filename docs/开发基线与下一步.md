## 当前运行与身份

真实 CRM：https://crm-java-api-crm-test.up.railway.app/?account=owner 。原生 PostgreSQL 18.6，Java 21 / Spring Boot 3.5.16，Vue 3 / TypeScript。

平台运营：https://crm-java-api-crm-test.up.railway.app/?account=platform-operator 。用于产品方开通企业、套餐、企业状态、续费、账号及平台运维，不自动读取客户企业的业务正文。

流程演示：https://binbin-crm-preview.zengb-12.chatgpt.site 。浏览器本地数据和演示身份，与真实 CRM 分开，保持原私有访问范围。

owner 是客户企业管理员的体验账号，选择企业后进入完整 CRM 工作台，另授予销售经理角色。企业管理员角色本身不自动取得销售业务权限。平台支持授权仍仅包含客户只读。

当前真实业务覆盖客户、联系人、线索转换、商机 / 阶段历史、跟进、待办、权限内报表、客户 CSV 导入、六类导出、私有附件、个人提醒、产品目录与报价 / 版本 / 中文 PDF / 指定经理审批 / 合同 / 分期计划 / 回款确认 / 冲正 / 对账；同时覆盖平台运营、组织权限、额度、续费和支持审计。Flyway V1～V9，34 张企业范围表强制 RLS，运行 / 迁移账号独立。未采用 SQLite。

## 下一开发阶段 P3

共五个大阶段 P0～P4，P1 和 P2 分别按 A～D 交付。本轮 P2-C / D 完成合同、受控变更、分期回款、异人确认、冲正、更正登记及对账。下一阶段 P3 包含工单、SLA、知识库、营销与系统集成，建议从 P3-A 服务工单与 SLA 开始。P4 为行业配置、客户门户及 AI。

正式 SMTP、独立密钥交接、异地副本、外部告警和真实客户试点仍待完成。备份支持 V5～V9 的精确表集合，完整恢复校验 50 表、34 张 RLS 表、9 次迁移、17 张商业表内容摘要和两份凭证。合同 / 回款与 SaaS 订阅续费分别存储、分别核对。

P1-D 当前限制包括固定导入列、仅客户导入、单文件 5MB、单次导出 5000 条、站内提醒、既定角色及销售阶段。没有自动支付、AI、任意自定义角色或外部消息投递。

## 验证原则

完整业务写入只在新建临时原生 PostgreSQL 18.6 中完成，使用独立凭据和虚构资料。写入前核对私网目标及初始三企业 / 六账号；验收后暂停新建企业、清除故障触发器、保存脱敏证据、停止临时进程并清空凭据。原预览仅做正常认证、自己的企业选择、GET 和退出。

最新证据见 P2-CD验收与部署记录.json、P2-CD隔离验收结果.json 和 P2-CD合同与回款开发交付.md；P1-D完整验收结果.json、P1-D验收结果.json 和 P1-D部署记录.json 为历史记录。浏览器视觉 / 鼠标端到端、压力测试、真实邮件投递、生产回滚、生产数据恢复及真实客户试点未执行。并发功能检查不等同于性能压测。P0～P1-C 的历史文档保持不变；本轮结果来自重新运行，不叠加历史数量冒充新增验收。

## 收费与试运营

套餐限制成员、客户和附件容量。初期人工核实订阅收款并续费；尚无自动支付。到期保留受控读取，拒绝业务写入；数据保留 / 清理政策后续确认。当前仍为虚构资料云测试环境，尚未完成正式收费试运营。
