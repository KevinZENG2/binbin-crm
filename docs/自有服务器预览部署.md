# 金拓CRM 0.23.0 · Ubuntu 预览部署

这是使用虚构资料的服务器验收包，包含应用、PostgreSQL 18 和私有附件存储。运行中的工作台、门户默认名称及邮件标题使用「金拓CRM」。已有镜像、安装目录和数据卷保留 `binbin-crm` 技术标识，便于在现有环境识别同一套服务。此说明不代表已经在目标服务器安装成功。

## 下载与核对

1. 打开 [GitHub 部署打包记录](https://github.com/KevinZENG2/binbin-crm/actions?query=workflow%3A%22Package+Ubuntu+CRM+preview%22)，选择 `ui/dark-glass-workspace` 对应目标代码提交且结果为 **Success** 的运行。登录 GitHub 后，在 **Artifacts** 中下载 `binbin-crm-vm-preview`。如早期产物已过期，请使用新的成功运行。
2. 解开外层 ZIP。在 `vm-output` 中找到 `image-lock.json`，核对 `sourceCommit` 与本次选择的提交一致；同次运行中的 `vm-https-acceptance.json` 记录 HTTPS 登录、租户边界与中文报价 PDF 验收结果。
3. 将 **同一个 ZIP** 中的 `binbin-crm-vm-0.23.0.tar.gz` 和 `binbin-crm-vm-0.23.0.tar.gz.sha256` 一起上传到服务器 `/root`。不要使用其他运行的校验和，tar.gz 与外层 ZIP 的 SHA-256 不同。
4. 将域名证书 ZIP `28013636_crm.jiayunsoft.com_nginx.zip` 单独放在服务器 `/root`。部署包不包含域名私钥或真实业务密码，首次启动只在服务器生成本地凭据。

下列命令针对首次部署。已安装的实例应保留现有目录和数据卷，不能直接覆盖或用此首次部署步骤重装。

## 在服务器执行

使用 root 执行以下整段命令。它会核对校验和、拒绝覆盖已有部署目录，并开始安装：

```bash
bash <<'CRM_INSTALL'
set -eu
cd /root
sha256sum -c binbin-crm-vm-0.23.0.tar.gz.sha256
if [ -e /opt/binbin-crm-preview ]; then
  echo '部署目录已存在，请保留目录并反馈结果，不要重复解压。'
  exit 1
fi
tar -xzf binbin-crm-vm-0.23.0.tar.gz -C /opt
python3 /opt/binbin-crm-preview/project/server/ops/vm/install_vm.py \
  --cert-zip /root/28013636_crm.jiayunsoft.com_nginx.zip \
  --apply --create-swap
CRM_INSTALL
```

安装器会：

1. 在小内存主机上创建专用 2GiB Swap 文件 `/swapfile-binbin-crm`，权限 0600，
   先备份现有 `/etc/fstab`，再追加该 Swap 的启动项；已有同名文件需要人工检查。
2. 校验镜像 ID 后使用预编译镜像启动独立 CRM、PostgreSQL 18、私有 HTTPS 存储与数据卷；
   应用只监听 `127.0.0.1:18080`，数据库和存储不发布公网端口。
3. 设置 HTTPS origin、Secure Cookie，关闭隔离验收模式，保持 AI 总开关关闭。
4. 校验域名、证书期限、系统信任链及公私钥配对，写入专用证书目录。
5. 增加 `/etc/nginx/conf.d/binbin-crm.conf`，通过 `nginx -t` 后 reload；
   同域名站点或不同的已有 CRM 配置会阻止安装，避免覆盖。
6. 初始化中文 PDF 字体，检查 0.23.0 健康接口，并用正确域名验证本机 HTTPS。

这台主机实测内存 1967MiB、可用约 1346MiB、无 Swap，根分区可用约 18GB。
应用内存上限 1GiB，专用 PostgreSQL 和测试存储各 256MiB，初始化工具另有限额。
现有 sub2api、PostgreSQL 17、Redis 和 Python 服务均保留，服务器不需要编译 Java、Node 或 Go。

安装成功会显示 `LOCAL_HTTPS_READY`，仅表示本机 HTTPS 检查成功。
随后还需验证公网 DNS、外网访问、登录与业务流程。结果写入
`/opt/binbin-crm-preview/deployment-status.json`。

若首次安装中断，可保留目录后重跑同一包内的安装器命令；不要重复解压覆盖，也不要删除数据卷。
安装器保留已经生成的密码和已有数据。

## 登录与边界

企业管理员用户名为 `owner`，初始密码由服务器管理员在本机读取：

```bash
cat /opt/binbin-crm-preview/project/.crm-preview/secrets/login_password
```

密码不需要发到聊天中。安装后按首次登录提示修改密码。
客户企业端使用 `/?account=owner`，平台管理端使用 `/?account=platform-operator`。

此包用于低流量的短期预览，包含虚构企业与客户资料，不自动迁入旧云环境的数据。
其他虚构演示账号共用初始密码，不应在该预览中导入真实客户敏感数据。
内部 CA 和服务证书有效期为 30 天，内置对象存储为固定的测试依赖。
正式运营前仍需更换为持续维护的存储服务，落实证书续期、加密备份及隔离恢复、
独立密钥保管、供应商密钥替换、真实 AI 费用核验、正式邮件与客户试点。
