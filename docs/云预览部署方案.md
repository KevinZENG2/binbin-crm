# 云预览部署方案

更新：2026-10-22。产品方要求更换云预览托管通道，继续开发与发布，不再以 Railway OAuth 恢复作为建立新预览的前提。

## 已有的可迁移基础

应用是 Vue 前端、Java 21 / Spring Boot 后端、PostgreSQL 18，仓库已有多阶段 `Dockerfile` 与 `Dockerfile.backup`。前端由应用服务同源提供，可在容器托管环境部署企业端、平台运营端、外部客户门户和流程演示端，无需重写现有业务功能。

P8 应用提交为 `8b308fb46c6b5d3dcbe20cc6aa6016352f326725`，0.23.0 / V30，Actions 第 66 次软件验收通过。这证明软件与原容器构建通过，尚不代表替代平台的部署和数据库权限验收通过。

## 替代通道：Render

已查到可安装的 Render 集成，并已提供安装连接入口。Render 支持从私有 GitHub 仓库构建 Docker 应用，提供托管 PostgreSQL，官方当前支持 PostgreSQL 18。新账号连接确认前，不创建云服务，不声称已有新预览网址。

连接后按以下顺序完成：

1. 确定预览资源配置、费用及实例可用性，在新的独立数据库和存储中部署，保持 GitHub 开发分支和 PR 草稿状态。
2. 初始化 `crm_migrator` 和 `crm_runtime` 两个数据库角色并验证权限。应用运行角色必须是无 superuser、无 BYPASSRLS 的 `crm_runtime`，业务表保留 `crm_migrator` 所有权和强制租户 RLS。先验证托管数据库的角色管理能力；如不能满足，则改用可控制角色的 PostgreSQL 容器或兼容托管库，不降低应用隔离检查。
3. 配置同源地址、HTTPS Cookie、新环境凭据和独立对象存储。AI 总开关先关闭，原 DeepSeek Key 不复用。
4. 发布指定代码，确认部署成功、健康接口 0.23.0 / V30、未登录业务接口受保护、企业与平台账号权限正确、附件读写成功。
5. 验证模型配置、受限预算、虚拟资料的真实 AI 调用、费用记账和业务保存；重新执行加密备份和隔离恢复。SMTP 和真实客户试点仍按实际验收记录交付。

Render 免费 Web 实例空闲后会休眠，免费 PostgreSQL 在创建 30 天后到期，因此免费配置仅用于短期预览，不能当作长期出租产品的生产配置。实际创建服务时须核对当前官方限制和资源费用。

## 旧数据和环境

新环境先建立独立预览。旧 Railway 数据、附件和历史备份不能从 GitHub 自动恢复；需恢复其管理或导出通道后，按已有备份恢复流程另行迁移和核对。没有拿到旧库快照和附件清单前，不标记旧数据迁移完成，也不覆盖或删除原预览。

历史备份的解密密钥按版本保留并独立保管。原 Railway 环境变量的安全事件与凭据轮换仍见 [P8 发布恢复记录](P8发布恢复记录.md)。更换托管平台不会撤销原供应商 Key，仍应在 DeepSeek 官方控制台撤销此前 Key。
