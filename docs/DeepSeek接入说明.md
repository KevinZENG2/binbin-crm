# DeepSeek 接入说明

默认供应商为 DeepSeek。2026-10-21 已收到产品方提供的密钥，保存至 Railway `crm-test` 的应用后端环境变量 `CRM_AI_DEEPSEEK_API_KEY`。本文和代码仓库不保存密钥值。

真实供应商独立连通验收已成功：模型列表 HTTP 200，虚拟文本生成 HTTP 200，模型 `deepseek-flash`，输入 21 Token、输出 2 Token，返回符合预期且带用量统计。没有发送真实客户资料。记录见 [真实连接验收](DeepSeek真实连接验收.json)。

应用服务仍运行 0.21.0。密钥等待下一次部署生效，总开关暂保持关闭。该独立测试不等于已验证线上 CRM 的权限、费用记账与业务保存链路，也未核对供应商真实账单。

## 产品方配置

1. 发布 P8 应用后，由平台运营账号从左侧「AI 模型与预算」添加 DeepSeek 模型。当前账号返回 `deepseek-flash`、`deepseek-v4-pro`；填写选择的模型标识、输入/输出人民币参考单价和单次输出上限。
2. 参考价格从官方最新报价换算并录入；输入、输出和缓存计费不同，系统预算按配置的保守参考值控制，不代替供应商账单。
3. 在同一入口管理提示词版本和灰度范围。新增九个场景默认关闭，先小范围试用再逐步扩大覆盖。
4. 完成模型与预算配置后开启服务器总开关 `CRM_AI_ENABLED`。企业管理员在左侧「企业 AI 设置」选择模型、设置月 Token 和参考费用预算、请求频率，再启用企业。
5. 先用虚拟资料检查 CRM 内实际生成、脱敏、计费记账、质量复核和保存，再做客户试点。

## 客户成员使用

从左侧「AI 助手」选择场景和可见的业务记录，点击「预览脱敏内容」，核对实际发送内容、供应商及模型，勾选同意后生成。确认五分钟有效，资料或配置变化后需要重新预览。

共 12 个场景，包含客户经营摘要、商机推进、线索研判、拜访准备、活动建议、跟进草稿、新建线索、工单回复与分诊、周报、异常解释和审批辅助。

例如选择「新建线索草稿」，输入“帮我新建李四线索，公司为某公司，行业为制造业，来源为展会”。生成后逐项编辑字段、补齐必填项，预览拟保存内容，再确认创建。跟进记录同样需要填写实际发生时间并确认保存。电话邮箱由使用人自行填写，编辑后的字段不再次发给模型。

审批辅助不代替主管审批，建议不会直接修改合同、回款、工单或发送邮件。需要复核的结果由主管记录依据和质量评分；敏感策略阻断的结果不能采纳。

## 接口约定

正式地址为 `https://api.deepseek.com/chat/completions`，Bearer 认证；采用 `messages`、`max_tokens`、`stream=false` 和 `thinking.type=disabled`。模型可配置，接口不提供任意工具调用或用户自定义供应商主机。

超时或无法确认的调用不自动重试，按预留值保守计入参考预算；已经发生的供应商调用不因输出被质量策略阻断而退款。
