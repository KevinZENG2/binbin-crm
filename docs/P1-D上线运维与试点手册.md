# P1-D 上线运维与试点手册

适用于 v0.6 云预览，2026-10-13。当前仍使用虚构资料，正式付费试运营另做客户验收。

## 每日检查

平台运营登录后打开「平台运维」。检查数据库、附件服务、最近 REMINDERS / DATABASE_BACKUP / BACKUP_RETENTION / RECOVERY_MAIL 的状态和错误编号。任务失败会显示页面提示；再次检查以新的 SUCCESS 记录为准。该页面不展示企业业务正文或对象地址。

提醒约每五分钟检查一次，按上海日期生成到期和逾期站内提醒。完成、重开、转交或权限撤销会重新计算可见性。同一任务版本、执行人和日期防重复。文件删除进入持久队列，失败后延迟重试，最长间隔一小时；重复删除对象不会重复释放容量。

用户明确授权后，原预览的自动全库加密备份已启用：每日 UTC 18:00，即北京时间次日 02:00，表达式 `0 18 * * *`。备份服务为复用的 `crm-db-bootstrap`，已确认 cronReady、无持续运行进程。首次即时执行已成功保存并读回加密对象，独立恢复核对 33 表、279 行、17 表强制 RLS 和 5 次迁移。平台运营 → 平台运维 → 最近任务记录，查看 `DATABASE_BACKUP` 的 SUCCESS、时间、字节数及校验摘要。应检查最近一次成功备份是否超过 26 小时；定时启动可能有数分钟偏差。当前没有对外短信或邮件告警。

## 备份设计与边界

`server/ops/backup.py` 使用 PostgreSQL 18 的一致性快照和自定义格式 pg_dump。按同一快照读取 READY 附件的引用，取回私有文件并验证字节数和 SHA-256，然后把数据库与附件打成包。任一文件丢失或被改动，本次备份失败。

整个包使用 AES-256-GCM 加密，随机 nonce，认证头和完整性标签；对象存储读回后再验证加密摘要、解密认证、数据库摘要及附件摘要。加密密钥只注入备份服务，Java API 和浏览器不持有密钥。备份不提供公开链接。

`crm_backup` 数据库账号已在用户明确授权后创建，使用 BYPASSRLS 读取所有企业和账号资料以生成完整快照。33 张表的 SELECT 权限及业务表无写权限已核对；仅 `sys_job_run` 可 INSERT / UPDATE，不得删除任务、创建 schema、创建数据库或管理角色，没有超级用户或角色继承权限。账号建立使用事务，setup 连接验证 TLS，临时管理员凭据已清空。它不是 CRM 登录账号。业务 API 仍使用不具备 BYPASSRLS 的独立运行账号。之前的自动审批拒绝记录属于授权前历史，现已由本轮明确授权解决。

原预览的加密备份保存在同一 Railway 项目的私有 `crm-files` 桶、`backups/preview/` 前缀，首份对象已保留；它不是跨账号或异地灾备。加密密钥只在备份服务私有变量 `CRM_BACKUP_ENCRYPTION_KEY` 中，数据库连接只用专用备份账号，Java API 和前端没有该密钥。已部署自动保留规则：保留 30 天并保护最近 3 份成功备份，新快照通过独立恢复后才清理匹配任务 UUID 的过期备份文件；保留任务审计与摘要。新版第一次实际定时执行结果尚待观察。独立密钥交接和异地副本尚待完成。密钥丢失会使已有备份无法恢复；轮换前应保留旧版本的受控密钥。授权前隔离演练的临时对象已清理，与现有预览的保留备份分开。

## 恢复流程

首次演练仅针对临时 `crm_acceptance` 数据库中的虚构资料，在没有卷、没有外部域名的临时容器中恢复到新的 PostgreSQL 数据库。已核对 33 张表、900 行、一个非空附件、5 次迁移及 17 张强制 RLS 表；确认对象读回、认证解密、篡改拒绝和无租户上下文的运行账号看不到客户。演练结束停止临时进程并清理测试对象，不覆盖原预览库。这属于授权前的隔离演练记录。授权后另对原云预览快照完成 33 表 / 279 行独立恢复，当前原预览没有附件，附件数为 0；非空附件恢复能力由此前隔离演练覆盖。两次恢复均未切换生产域名或覆盖源库。

手动恢复工具为 `server/ops/restore_backup.py`。它只允许明确指定的空 `crm_restore_*` 数据库和新 `restore-*` 文件前缀，不允许目标 `/railway`。新实例需预先准备 runtime / migrator / backup 角色。工具验证备份 SHA-256 和解密认证，将附件复制到新前缀并改写新库引用；取消原删除队列，撤销恢复后的会话和找回链接，避免恢复实例处理原文件。

配置项包括 CRM_RESTORE_DATABASE_URL、CRM_RESTORE_CONFIRM_DATABASE、CRM_RESTORE_OBJECT_PREFIX、CRM_RESTORE_BACKUP_KEY、CRM_RESTORE_BACKUP_SHA256，以及备份密钥和 S3 的私有配置。凭据通过私有环境变量提供，不写到命令行、日志或源码。

恢复完成后，先在新实例启动 API（CRM_SEED_ENABLED=false；CRM_OBJECT_PREFIX 使用新前缀），验证登录、租户隔离、客户及文件下载，再决定是否切换域名。失败的新恢复库需检查或丢弃后重做，不能开放给客户。当前每日备份保持 `CRM_BACKUP_REHEARSAL=true`，每次备份读回校验后都在本地新库完成恢复核对并停止临时 PostgreSQL；没有持久卷或公开端口。自动演练与手动切换工具是不同验证范围；手动恢复脚本和生产域名切换尚未实际执行。

## 发布和回滚

源码已经由现有项目的关联 Git 保存。主应用 Dockerfile 构建 Vue 和 Java，最终使用非 root JRE；Dockerfile.backup 构建运维镜像。`.github/workflows/verify-and-container.yml` 准备了前后端检查、两类容器构建，以及手动触发的按 commit 发布和 digest 记录。

当前没有接入正式 GitHub 仓库 / 容器注册表。该流水线没有在线运行；当前云预览继续使用经过 SHA-256 校验的源码包和官方 Maven / Java 21 镜像。上线时应转为仓库构建或固定 image digest，并设置分离的测试 / 正式环境。

升级前记录当前部署 ID、源码摘要、变量名和成功备份；通过隔离原生验收后再发布。更新源码包变量后，应创建读取新配置的部署；不要重启旧快照去读取新摘要。

应用回滚优先切回上一应用部署及其对应变量快照，数据库保留前向兼容的迁移。V5 是增量表和字段；不要删除 V5，也不要在已有业务库执行 Flyway clean。旧版本是否可运行必须先在恢复库验证；业务数据已变更或迁移不兼容时，使用新恢复实例评估数据损失，再切流。本轮没有覆盖预览数据库，也没有执行正式业务版本回退。

## 邮件找回启用

配置 CRM_SMTP_HOST、PORT、USER、PASSWORD、FROM 和 TLS / SSL，以及 CRM_PUBLIC_BASE_URL。生产 SMTP 必须使用 TLS / SSL，公开链接必须为 HTTPS。未配置发件服务时，登录页面明确显示联系管理员，保持邮件找回关闭。

平台运营在「登录账号 → 绑定找回邮箱」填写已经线下核验属于该账号的邮箱与说明；绑定会撤销该账号所有会话和旧找回链接。系统没有自动证明邮箱归属，不应未经核验代填。

找回申请统一返回相同提示，不暴露账号是否存在。每个账号每 15 分钟最多处理五次，链接 30 分钟有效、单次使用，数据库只保存令牌摘要。成功找回撤销旧会话、其他找回链接，并解除登录失败限流。投递失败使该令牌失效并记录任务错误。本轮使用内部假 SMTP 验证，未向客户发送邮件。

## 首家企业试点

|步骤|负责人|验收结果|
|---|---|---|
|开通与套餐|产品方平台运营|真实企业管理员账号、成员 / 客户 / 附件额度和到期日准确|
|组织与权限|客户企业管理员|经理、销售、只读成员的数据范围和字段权限符合实际组织|
|试导入|客户管理员 / 经理|使用脱敏小样本核对 CSV 模板、错误行、负责人和入库结果|
|销售流程|客户销售|线索转换、客户联系人、商机阶段、跟进和待办能完成完整业务流程|
|报表核对|客户负责人|按创建日、成交日和待办截止日核对统计口径，不把阶段快照当历史转化漏斗|
|附件与提醒|客户销售 / 管理员|上传、下载、共享、撤销权限、容量及到期提醒符合预期|
|账号恢复|产品方与客户管理员|核验邮箱，配置正式发件后验证真实邮箱投递与找回|
|运维与恢复|产品方运营|备份成功、独立恢复可验证、失败可定位且有责任人|
|签署试点结果|客户负责人|记录设备 / 浏览器体验、业务缺口和可接受的限制，再决定付费上线|

当前没有代客户创建正式租户、邀请真实成员或发出试点通知。试点企业名称、管理员、业务样本和验收反馈需由实际客户提供。P2 可在试点反馈基础上开发产品报价、审批、合同与回款；合同回款与 SaaS 订阅收费分别处理。

## P2-A 运维更新（2026-10-13）

当前主应用 v0.7 运行 V6。备份与手动恢复精确识别 V5 / V6，分别校验完整表集合、迁移、属主和强制 RLS；V6 为 38 表 / 22 张强制隔离表。备份账号的未来表 SELECT 默认权限沿用，无新增业务表写权限。原每日备份服务仍保持 `0 18 * * *`、原加密密钥、原 `/railway` 目标和 `backups/preview/` 前缀；升级后的首次真实定时执行待观察。隔离 V6 已实际恢复 38 表、257 行、1 个非空附件，并核对产品与报价 5 张表的内容摘要；测试对象已清理，原保留备份未删除。

中文 PDF 字体是固定公开授权的系统依赖，在桶中按内容摘要命名。新桶恢复后先执行 `server/ops/publish_quote_font.py` 重建同摘要字体，再验收 PDF；字体出处、转换参数与许可见 `server/ops/assets/`。字体不作为客户附件保留 / 删除对象。V6 增量迁移不可通过删除表回滚；切回旧应用仍需先在独立恢复库验证。细节及最新脱敏证据见 [P2-A产品与报价开发交付.md](P2-A产品与报价开发交付.md) 和 `P2-A验收与部署记录.json`。
