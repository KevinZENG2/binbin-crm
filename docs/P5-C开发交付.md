# P5-C：客户档案与互动协同

版本：0.16.0。入口位于客户企业端左侧“客户中心”，在客户行点击“360°档案”；线索中心和商机列表点击“跟进档案”。平台运营端不处理企业客户资料。

## 已交付

| 能力 | 操作和约束 |
| --- | --- |
| 客户档案 | 同一页展示客户资料、生命周期、标签、联系人、商机、待办、跟进、报价、合同、工单、附件及时间线；每类关联列表最多读取最近 100 条，仍受原模块权限和客户可见范围控制。 |
| 生命周期 | 潜在、活跃、沉睡、流失四阶段；变更需可编辑、版本一致和填写原因，保存变更人、时间和历史。 |
| 查重与合并 | 在可见客户中按规范化名称或有权限读取的信用代码匹配。企业管理员或有全量写权限的经理，在可编辑、联系人写权限与信用代码/备注读取权限下才能合并。来源客户如已有商机、活动、待办、报价、合同、工单、附件、跟进、门户账号或历史线索转换，拒绝合并。简单来源的联系人、标签、扩展值、共享关系保留到目标客户；来源归档，保留审计和历史外键。 |
| 标签 | 可在客户档案勾选并保存客户标签；标签名称与颜色在行业配置中心统一维护，写入仍受客户编辑权限控制。 |
| 联系人关系 | 新增决策角色、影响力、联系偏好，可在联系人表单编辑，并在客户档案查看。 |
| 三级跟进 | 对线索、客户、商机建立未来跟进计划或实际跟进记录；完成计划必须提供结果，系统在同一事务中关闭计划并建立一条结果记录，防止重复完成。 |
| 时间线 | 按时间汇总有权查看的跟进、旧活动、待办、附件、商机、报价、合同和工单；过期未完成计划高亮并显示数量。可给记录关联该客户的已有附件并从时间线下载。 |

## 数据和接口

- 迁移 `V20__customer_collaboration.sql`：客户阶段和合并指向、生命周期历史、联系人关系字段、三级跟进表；新表启用强制租户行级隔离，合并后的来源客户不占活跃客户额度。
- `GET /api/v1/customers/{id}/profile`、`GET /api/v1/customers/{id}/duplicates`、`PATCH /api/v1/customers/{id}/lifecycle`、`POST /api/v1/customers/{id}/merge`。
- `GET /api/v1/followups/{LEAD|CUSTOMER|OPPORTUNITY}/{id}`、`POST /api/v1/followups`、`POST /api/v1/followups/plans/{id}/complete`。
- 写入沿用企业状态、订阅、CSRF、记录权限、关联对象和版本检查；跨企业外键与数据库 RLS 双重隔离。

## 验收步骤

1. 企业管理员登录客户企业端，在客户中心打开档案，检查关联列表和时间线，仅出现该角色可读的数据。
2. 调整生命周期并填原因，刷新后核对历史和版本。线索、客户、商机分别建立计划，完成后检查计划与结果各一条，逾期计划显示提醒。
3. 编辑联系人的决策角色、影响力和联系偏好，返回客户档案核对。上传客户附件后关联跟进记录并下载。
4. 创建两个没有业务关联的简单客户，核对查重、输入目标全名和原因，合并后来源不出现在客户列表且额度减少；再尝试合并已有商机或工单的客户，应得到冲突提示且原数据完整。
5. 使用普通销售、只读成员、其他企业账号分别检查字段、模块权限、写入限制与租户隔离。

## 范围与下一步

时间线一次显示最近 250 项，每个旧模块最多拉取最近 100 条；逾期计划在档案内提示，跨页面推送与自动提醒策略留待后续通知增强。P5-D 将处理商机产品明细、阶段准入、加权预测、推进审批与报价毛利和折扣规则。
