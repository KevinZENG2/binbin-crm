# 彬彬 CRM · P1-B 联系人与线索交付

版本 v0.4，2026-10-13（上海时间）。保留 Java 21 / Spring Boot、Vue 3 / TypeScript 和原生 PostgreSQL，继续在现有云预览开发。

真实工作区：https://crm-java-api-crm-test.up.railway.app/?account=owner

## 本轮新增

|模块|可操作内容|入口|
|---|---|---|
|联系人|新增、查看、编辑、姓名 / 客户 / 电话 / 邮箱搜索、分页、设置主要联系人|顶部“联系人”，或客户列表“联系人”|
|客户关联|通过搜索和分页选择可编辑客户；从联系人返回客户|联系人资料中的“所属客户”|
|线索|新增、查看、编辑、负责人、状态筛选、搜索、分页|顶部“线索中心”|

客户弹窗、管理弹窗与新增业务弹窗均使用屏幕居中的遮罩、限制高度和内部滚动。标题及底部操作按钮保持在窗口内，打开时锁定背景滚动，保留 Escape、键盘焦点限制及关闭后焦点恢复。

## 操作路径

1. 使用已有 `owner` 账号和此前交付的密码登录，选择“星澜科技 · 测试企业”。
2. 在“客户中心”新增或选择可编辑客户，点击该行“联系人”，再新增联系人；也可在顶部“联系人”选择客户。
3. 在“线索中心”新增公司与联系人需求，填写来源、负责人和联系方式。
4. 查看 / 编辑线索，先保存为“已联系”，再保存为“已确认合格”。
5. 点击“转为客户”，选择新建客户或关联已有客户，确认转换；完成后可直接查看客户和联系人。

未拥有相应模块权限的账号不显示业务入口。`tech-admin` 的企业管理角色不会自动获得业务权限；销售与只读账号按当前角色配置访问。旧标签页可按 Ctrl+F5 刷新。

## 权限边界

联系人需同时满足联系人模块读取开关及所属客户读取权限；编辑还需联系人模块写入及所属客户写入权限。客户共享、共享期限、撤销、转交、角色和部门变化会在后续请求重新计算联系人访问范围。每个客户最多一位主要联系人；替换时，同一事务撤销原主要标记并更新其版本。

线索有独立的读取 / 写入开关，按角色中的全部、本部门或本人记录范围分别合并。本部门不包括子部门；本轮没有单独共享线索。多个角色扩大读取范围时，不会自动扩大写入范围。只读角色不能获得任何业务写入。

现有客户的信用代码和客户备注权限只作用于客户字段。联系人、线索的联系方式和备注属于各自模块，按模块及记录权限整体保护，本轮没有逐字段权限或自定义角色。转换时仅在拥有客户备注写入权限时复制线索备注到新客户；联系人保留线索中的联系信息。

只读支持授权继续限定客户范围，不能读取或写入联系人和线索。订阅到期后允许受控查看，拒绝联系人、线索和转换写入。企业暂停后业务访问全部拒绝。

## 状态与转换事务

|当前状态|允许保存为|转换|
|---|---|---|
|新线索|新线索、已联系、不合格|不允许|
|已联系|已联系、已确认合格、不合格|不允许|
|已确认合格|已确认合格、已联系、不合格|允许|
|不合格|不合格、新线索|不允许|
|已转客户|原记录只读|不能再次转换|

转换请求要求 `Idempotency-Key` 和当前 `expectedVersion`，只能选择一种目标模式。新建客户需客户名称、等级和负责人；关联已有客户需目标客户编号和该客户写入权限。

服务端先锁企业行，重新检查身份和订阅，再锁线索。在同一事务完成客户新增或关联、联系人新增、线索状态及结果编号更新、审计和请求结果保存。新建客户沿用客户额度及事务计数；关联已有客户不新增客户用量。任何步骤失败，相关客户、联系人、计数、线索和本次请求记录一起回滚。

相同请求编号与相同内容返回原转换结果；内容变化冲突。不同请求编号并发转换同一线索，最多一项成功。已转换线索保留原始信息及转换时间；关联结果按当前客户和联系人访问权限返回。由转换生成的联系人可编辑联系方式，不能更换客户，以保留来源关联。

转换会生成一位联系人，不按姓名、电话或公司名称自动合并已有记录。不同线索可能指向同一家公司，用户可选择“关联已有客户”；跨线索查重及自动合并留待后续需求。

## 接口和数据

|接口|实现|
|---|---|
|`GET /api/v1/contacts`|搜索、分页、可选客户筛选；按客户权限过滤|
|`GET /api/v1/contacts/{id}`|资料与当前编辑 / 更换客户能力|
|`POST /api/v1/contacts`|幂等新增，所属客户与主要联系人检查|
|`PATCH /api/v1/contacts/{id}`|显式版本编辑，受控客户关联及主要标记替换|
|`GET /api/v1/leads`|搜索、状态筛选、分页及记录范围|
|`GET /api/v1/leads/owners`|当前范围内有效的线索负责人|
|`GET /api/v1/leads/{id}`|线索资料及受控转换结果|
|`POST /api/v1/leads`|幂等新增，服务端固定初始状态|
|`PATCH /api/v1/leads/{id}`|显式版本、状态机和负责人校验|
|`POST /api/v1/leads/{id}/convert`|原子转换及防重复|
|`GET /api/v1/customers/options`|可搜索、分页的客户选择；默认仅可编辑客户|
|`PATCH /api/v1/workspace/role-policies/{role}`|新增联系人及线索开关，未提交新字段时保留现有值|

Flyway V3 新增 `crm_contact`、`crm_lead` 和四个模块权限开关。联系人与客户、线索与成员、转换结果与同客户联系人均使用带企业编号的复合外键。两张新增业务表强制 RLS，运行角色无表所有权、超级用户或 BYPASSRLS；启动守卫核验九张范围表。V3 从既有客户政策初始化新模块开关，不修改既有客户权限；角色版本递增使旧编辑请求冲突。新企业和开发初始化同时写入新开关。

管理、认证、CSRF、工作区过期检测和错误协议沿用原实现。业务审计记录动作、资源、版本和追踪编号，不保存联系正文或密码。联系人和线索暂未设置独立套餐额度，成员与客户额度继续生效。

## 验证与边界

已通过 Java 19 项协议及权限测试、Vue / TypeScript 构建。全新的隔离原生 PostgreSQL 16.15 已完成 P0 回归 45 项、P1-A 回归 61 项、P1-B 验收 87 项及停机前数据库 checkpoint 7 项。逐项结果见 `P1-B完整验收结果.json`，摘要见 `P1-B验收结果.json`，部署与线上资源核对见 `P1-B部署记录.json`。

新增验收覆盖客户关联、主要联系人及版本、客户共享 / 转交继承、模块与角色撤销、部门及组合角色范围、状态机、旧版本、跨企业引用、受控转换结果、到期与支持访问限制、九表 RLS、复合外键和 JDBC TLS。

通过数据库故障注入验证联系人插入失败时，刚创建的客户、额度计数、线索变更和请求结果一起回滚；移除故障后同一请求编号可成功重试。验证同键与异键两个并发请求、转换与普通新增竞争最后一个客户名额。仅证明这些并发场景，不代表性能压测。

测试只写入新建临时库中的虚构资料。验收套餐、企业、成员和登录密码与原预览独立；完成后暂停新建企业，保存结果和审计摘要，停止临时服务并清空私有凭据。数据库故障触发器已删除，不进入发布包。

原预览 PostgreSQL 18.6 已成功从 V2 迁移到 V3，19 项 Java 检查再次通过，发布后 HTTPS 只读接口检查 23 项通过，线上 HTML、JavaScript 和 CSS 与最终构建逐字节一致。原预览不作为完整业务写入验收目标。浏览器视觉 / 鼠标端到端、压力测试和生产备份恢复未执行；本环境缺少可用的浏览器自动化能力。
